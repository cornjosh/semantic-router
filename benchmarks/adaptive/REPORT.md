# 分类与路由实测报告（2026-10-23）

结果来自本机 NVIDIA A10、8 CPU，模型由 ModelScope 固定版本下载。完整方法、许可证与重跑命令见 [README](README.md)，文件哈希和环境见 [provenance](provenance/)。

## 公开意图分类

实际执行项目的 `SignalPipeline → HTTP embedding → GPU`，每次请求现场推理。BGE CLS + L2 归一化，按类别取最多 5 条训练示例，seed=42，最大余弦匹配，无微调。中文 `cooking_query` 只有 4 条可用训练语句，因此共 299 条原型；CLINC150 为 750 条，BANKING77 为 385 条。

| 数据集 | 测试 ID 数 | 准确率 | macro-F1 | 无效输出 | HTTP 信号 p50/p95/p99（ms） |
|---|---:|---:|---:|---:|---|
| MASSIVE zh-CN | 2711 | 47.99% | 48.06% | 0 | 4.72 / 5.56 / 6.31 |
| CLINC150（已知意图） | 4498 | 84.28% | 83.94% | 0 | 7.73 / 9.04 / 11.15 |
| BANKING77 | 3072 | 78.65% | 78.33% | 0 | 7.23 / 8.42 / 10.18 |

CLINC 延迟包含额外 1,000 条 OOS，共 5,498 次测试请求。每次评测并发 1、预热 10 次；预热包括原型编码，原始时长保存在结果中。表格时长包含信号流水线、HTTP、GPU 和分类计算，不包含持久化决策或 Higress。

### 数据审计与可比性

| 数据集 | 原始 train/dev/test | 去重后 train/dev/test |
|---|---|---|
| MASSIVE zh-CN | 11514/2033/2974 | 11022/1886/2711 |
| CLINC150（已知意图） | 15000/3100/5500 | 15000/3097/5498 |
| BANKING77 | 8030/1969/3080 | 8030/1969/3072 |

BANKING77 官方 train 为 10,003 条，规范化去重后为 9,999 条，再按类别划分 8,030 train 和 1,969 dev；官方 test 为 3,080 条。CLINC 表内 dev/test 包含 OOS。去重以规范化文本为键，优先 train、再 dev、再 test；剔除记录写入每份 JSON。MASSIVE 的 60 个训练标签中 `cooking_query` 没有 held-out 支持，macro-F1 仍按固定的 60 类计算，support 为 0 的类别记 0。

早期已在未去重的 MASSIVE test 上看过 49.23% 的探索性基线；本报告不将同一 test 宣称为从未接触的盲测。正式协议在后续评测前固定，未根据 test 选择示例数量、模型或阈值。去重及示例抽样变化使本报告中文结果变为 47.99%，与未过滤的官方榜单不可直接比较。

### 未知意图拒识

拒识仅使用 CLINC dev 的已知意图和 100 条 OOS 选择阈值，测试阶段冻结。

- 最大余弦阈值：0.740012。
- OOS 召回率：77.20%；误接受率：22.80%（1,000 条）。
- 已知意图覆盖率：91.86%；接受部分准确率：86.45%。
- ID 接受 / OOS 拒识平衡指标：84.53%。

这个阈值是当前数据与模型的操作点；余弦并非概率，也没有做模型成功率校准。22.80% 的 OOS 误接受说明它仍不能独立承担严格的业务边界判断。

### 错误类型

各类别 F1、支持数与完整混淆摘要存入结果。主要错误如下：

- MASSIVE zh-CN：`calendar_set` → `alarm_set`（71）；`play_music` → `music_settings`（43）；`email_query` → `email_sendemail`（43）。
- CLINC150（已知意图）：`share_location` → `current_location`（16）；`pto_request` → `pto_request_status`（15）；`play_music` → `next_song`（13）。
- BANKING77：`beneficiary_not_allowed` → `failed_transfer`（19）；`supported_cards_and_currencies` → `fiat_currency_support`（17）；`exchange_via_app` → `exchange_charge`（14）。

这些错误多是语义相邻但操作不同的意图。中文少示例 BGE 基线明显不足；后续应使用独立验证集评估更充分的领域示例、专门分类器或更强语义模型，并加入真实业务分布。现有结果不支持“中文分类已达到生产精度”的结论。

## 合成路由机制

真实 HTTP + 本地 SQLite；每种 20 次预热后测量 200 次，并发 1。质量标签和后端时延由脚本给定；不是外部模型真实质量或推理速度。路由请求计时不包含随后上报的观察/反馈 HTTP。

| 场景 | 路由 p50/p95/p99（ms） | 测量段外部信号调用 | 最终选择 |
|---|---|---:|---|
| static | 3.41 / 4.30 / 4.57 | 0 | {'basic-east': 200} |
| load | 3.14 / 3.85 / 5.23 | 0 | {'basic-west': 200} |
| learning | 3.51 / 4.31 / 4.84 | 0 | {'reasoning-east': 200} |
| signals | 24.20 / 24.62 / 24.90 | 200 | {'basic-west': 200} |
| shortcut | 3.39 / 3.92 / 6.08 | 0 | {'reasoning-east': 200} |

所有场景零错误。静态路由一直选择 synthetic TTFT=2,000ms 的 east；负载路由收到第一次观测后选择 synthetic TTFT=100ms 的 west。学习场景在 basic 的一次失败质量反馈后改选 reasoning；轨迹保存于 `warmup_decisions`。这证明反馈影响选择及状态持久化路径，不证明一个反馈足以代表真实模型整体质量。20ms 外部信号被工具 shortcut 完全跳过。

## 真实 Higress 代理对照

固定官方 Higress 2.2.5 和实际 Go Wasm，分类服务使用 SQLite。fixture 在 20ms 后发送首个内容，再等 2ms 发送 DONE；没有模型生成。每组 20 次预热、200 次测量。

| 路径 / 并发 | 客户端 TTFT p50/p95/p99（ms） | 总时长 p50/p95/p99（ms） | 请求/秒 | 错误 / 字节一致 |
|---|---|---|---:|---|
| direct_c1 | 20.49 / 20.67 / 20.77 | 22.66 / 22.91 / 23.06 | 44.03 | 0 / 200 |
| higress_wasm_classifier_c1 | 24.99 / 35.00 / 40.98 | 27.42 / 37.28 / 43.28 | 35.16 | 0 / 200 |
| direct_c8 | 21.58 / 22.16 / 22.55 | 24.08 / 24.63 / 25.00 | 325.43 | 0 / 200 |
| higress_wasm_classifier_c8 | 53.71 / 201.51 / 486.52 | 56.24 / 204.24 / 489.17 | 94.22 | 0 / 200 |

单并发中位 TTFT 开销约 4.50ms；并发 8 的代理路径 p99 约 487ms，不能从单并发中位数推导高负载 SLA。默认 SQLite 使用本机旧运行库对应的 FULL + rollback journal，写入竞争及异步观测都属于该测量配置。没有做因果性能剖析，不能仅凭此表将所有尾延迟归因于某个组件。跨节点 HA 的性能需在实际 etcd、网络和业务负载下另测。

## 结果与复现文件

`results/*.json` 保存指标、原型摘要、审计、配置和运行代码信息；`*.predictions.json.gz` 保存逐样本真实标签、预测、置信分数、错误码和耗时，不包含原始语句。压缩前后 SHA256 见 `predictions-manifest.json`。运行脚本会写未压缩 predictions JSON，可与清单核对。分类脚本固定在 `2f6719d`；网关基准脚本在 `b5c1689` 提交，其运行时工作树脚本 SHA256 在 JSON 中记录。模型版本与数据文件都按 manifest 校验。

外部 API 成本为零。本报告覆盖意图分类与机制验证，不是完整用户问答质量评估。部署、故障切换、完整回归与独立审查的证据入口见 [交付核对](../../docs/research/2026-10-23-adaptive-acceptance.md)。
